# البنية التقنية المقترحة

اقتراح أولي قابل للنقاش والتعديل حسب الميزانية وحجم الفريق — ليس قراراً نهائياً.

## الواجهة الأمامية (Frontend)
- **الويب:** React / Next.js — لإعادة بناء الشاشات الحالية كتطبيق فعلي متصل بالبيانات الحقيقية بدل HTML ثابت.
- **الجوال:** React Native أو Flutter لتطبيق واحد يعمل على iOS وAndroid معاً (أسرع من بناء تطبيقين منفصلين).

## الواجهة الخلفية (Backend)
- **API:** Node.js (NestJS) أو مشابه، عبر REST أو GraphQL.
- **قاعدة البيانات:** PostgreSQL للبيانات العلائقية (المستخدمون، المنشورات، المتابعات) + Redis للتخزين المؤقت والجلسات.
- **التوثيق (Auth):** OAuth عبر Google وApple (مطابقة لأيقونات تسجيل الدخول في شاشة الترحيب) + JWT للجلسات.

## المحادثات الفورية
اتصال WebSocket (مثل Socket.io) أو خدمة مُدارة جاهزة (Pusher/Ably) لتقليل وقت البناء في البداية.

## الفيديو والـReels
- تخزين كائنات (Object Storage متوافق مع S3) للملفات الأصلية.
- خط معالجة (Pipeline) لتحويل الفيديو لعدة جودات (ffmpeg أو خدمة سحابية مثل AWS MediaConvert).
- شبكة CDN للبث السريع حول العالم.

## الألعاب
تضمين ألعاب HTML5 داخل إطار (iframe/WebView) كخطوة أولى أسرع من بناء محرك ألعاب خاص.

## البنية التحتية
- حاويات Docker + بيئة تكامل/نشر مستمر (CI/CD) — مثل GitHub Actions.
- استضافة سحابية (AWS / GCP / Azure) مع فصل بيئات التطوير والإنتاج.

## الإشراف على المحتوى
طابور مراجعة (تلقائي + بشري) لفحص المنشورات والفيديوهات المرفوعة قبل الانتشار الواسع، لتفادي إساءة الاستخدام.
